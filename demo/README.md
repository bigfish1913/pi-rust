# demo/

The README's demo material, kept as **code** so it can be regenerated instead of
re-shot.

| File | What it is |
| --- | --- |
| [`sdk.tape`](sdk.tape) | [VHS](https://github.com/charmbracelet/vhs) script → `docs/images/rpi-sdk-demo.gif` |
| [`rpi.tape`](rpi.tape) | VHS script for the interactive TUI → `docs/images/rpi-demo.gif` (needs a model) |
| [`transcript.txt`](transcript.txt) | Real stdout of the two offline examples, embedded in the README |

## Regenerate

```bash
task demo-transcript   # demo/transcript.txt  (offline, deterministic)
task demo              # docs/images/rpi-sdk-demo.gif
```

`task demo` needs `vhs`, `ttyd` and `ffmpeg`:

```bash
scoop install vhs ttyd ffmpeg     # Windows
brew install vhs                  # macOS (ffmpeg via brew)
```

## Why the demo is offline

`sdk.tape` records the `faux` provider — a deterministic in-process stand-in — so
the GIF shows a **real** agent loop and a **real** tool round-trip against the OS
filesystem, with no API key and no network, and it produces the same frames every
time. A demo that needs credentials cannot be regenerated by a contributor and
cannot be diffed in CI; this one can.

`rpi.tape` is the exception: an interactive TUI session is only interesting with a
real model, so it needs whatever provider is configured (`~/.rpi/agent/models.json`
or `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`). Its output is not reproducible, which
is exactly why it is not what the README leads with.

## Capturing the transcript instead of a GIF

`demo/transcript.txt` exists because a fenced code block is:

- copy-pasteable (a reader can run the two commands immediately),
- greppable,
- reviewable in a diff, and
- regenerable in CI (`scripts/demo-transcript.sh` fails loudly if a command
  breaks).

A GIF is none of those. The README carries both: the GIF for the shape of the
thing, the transcript for the evidence.
